# 失败请求：零费用，正常展示套餐费率

## 业务口径

用户确认：请求失败时，本次费用为 0；但模型的价格套餐没有消失。
列表和详情仍须展示套餐名称、时段规则、输入/输出单价等信息。
**费用为零不等于没有费率，也不等于未定价。**

| 记录 | 本次费用 | 套餐与费率 | 扣款 |
| --- | --- | --- | --- |
| 成功 | 原有计费结果 | 调用时快照 | 按原有规则 |
| 失败且有价格 | 0 | 正常显示，零用量价格项也保留 | 否 |
| 历史失败且无快照 | 0 | 按模型、端点、日志时间重建可用参考费率 | 否 |
| 模型确实没有可用价格 | 0 | 不虚构费率 | 否 |

## 实现边界

- 失败写入 `estimated_cost=0`，不再使用非零标记价。
- 失败价格快照保留原计费模式、套餐规则、币种、单价与用量，
  每项金额、小计、总计归零，`charged=false`。
- 没有返回 token 用量的 502，也要保留配置过的输入/输出费率项。
- 历史失败的 `estimated_cost=NULL` 不能成为跳过费率重建的条件。
- 历史参考费率只补到列表响应，不回写账务；标记 `reconstructed=true`，
  详情注明不是原始快照。它依赖现有价格配置，不保证等于历史已删除或修改的价格。
- 前端根据失败状态独立显示零费用，防御旧版错误快照中的非零总计；
  套餐摘要直接展示费率，不再把存在快照标成「已计费」。
- 成功请求的估算、扣款和零用量行为不因失败费率展示而改变。

## 回归检查

- 无用量 502：费用为 0，已配置的输入/输出单价仍存在。
- 高级套餐失败：保留套餐名、规则与时段，费用仍为 0。
- 失败有 usage：保留用量供排障，但金额、余额扣款为 0。
- 历史失败无成本字段：仍尝试重建参考费率。
- 旧版非零失败快照：界面费用为 0，不显示「已计费」。
- 桌面与移动端都展示套餐费率；详情零费用与单价互不混淆。

## 纠正旧实现

0.6.80–0.6.82 把失败快照当作非零成本并使用标记价，且删除零数量价格项，
导致无用量失败行仍显示「无价格快照」。这不是用户要求的口径，现已废弃。
