# 模型映射批量公开名

渠道「模型映射」弹窗的「配置映射」页签里，一行 = 一条「上游模型 → 公开名称」关系。
公开名称支持**用逗号一次写出多个名字**，一个上游模型因此可以一次映射成多个公开名，
不用为同一个上游模型重复加行。

## 使用方式

1. 渠道列表 → 「发现与映射模型」；
2. 切到「配置映射」页签，「添加映射」，左侧选上游模型，右侧填公开名称；
3. 公开名称用逗号分隔，例如 `space-bunny,free`；
4. 「保存模型配置」，保存成功后展开成两条独立映射：`space-bunny-free → space-bunny`
   与 `space-bunny-free → free`。

半角 `,` 与全角 `，` 都算分隔符，前后空格会去掉；空片段（`a,,b`）与重复片段
（`a,a`）自动丢弃，填写顺序即展开顺序。一行里只剩分隔符（`,`）视为没填，
保存时报「映射配置不完整」。保存后的结果仍是数据库里一条条独立记录，
再次打开弹窗会按公开名回填成多行，不会保留逗号写法。

## 语义与限制

- 展开发生在服务端：`PUT /api/channels/{id}/models/selection` 的每条 `publicName`
  都会被按逗号切分，等价于客户端提交多条映射；直接调接口同样支持逗号写法。
- 每个公开名都是独立的路由与计费主键：它们各自有价格、各自的关闭时段、
  各自出现在 `/v1/models` 与模型管理里，因此批量写多个名字后要分别确认配置。
- 「关闭时间」页签列出的是展开后的每个公开名，按名字单独配置时段；
  若接口提交的是逗号写法，该时段会落到这一批展开出的每个公开名上。
- 单个公开名仍限长 191 字符，超长直接报错；展开后的总条数上限 2000。
- 重复映射（同一个上游模型 + 同一个公开名）依旧报错，逗号前后写重复名字不会自愈成两条。

## 实现位置

- `internal/logic/channel/models.go`：`splitPublicModelNames` / `resolvePublicModelNames`，
  映射与关闭时段解析都走同一套逗号切分。
- `frontend/src/lib/models.ts`：`splitPublicModelNames` / `expandModelMappingRows`，
  「关闭时间」清单与保存请求共用，保证界面显示与提交结果一致。
