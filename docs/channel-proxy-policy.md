# 渠道强制代理出口策略

## 安全约束

渠道配置代理后，所有由 AiFerry 服务端发出的该渠道上游请求都必须经配置代理。代理地址非法、密文损坏、解密后为空、代理不可达、代理认证失败或读取当前渠道策略失败时，停止请求并返回错误；**不允许自动回退直连**。

覆盖范围包括正式调用及流式请求、余额/费用/套餐额度、模型发现/同步、测试与健康巡检、渠道价格同步、签到与定时签到、登录设备码申请/轮询/换票、令牌刷新、异步视频任务查询，以及跨域媒体下载。跨域下载移除鉴权头，但保留渠道代理，不能用“资源无需鉴权”推导“资源可以直连”。

多代理转发仅可在配置列表内轮换，列表耗尽即失败。管理查询当前使用第一个配置代理，不会为提高成功率改成直连。HTTP/HTTPS 代理显式覆盖环境代理和 NO_PROXY；SOCKS5/SOCKS5H 由代理解析上游域名，传播请求取消/超时，并清除可能绕过 SOCKS 的自定义 TLS 拨号器。

## 配置时效

真正构建上游客户端前，从当前节点数据库读取最新渠道代理，不相信路由缓存、定时任务或异步任务持有的旧渠道快照；读取失败立即拒绝上游请求。只有数据库明确记录未配置代理时，才使用原有无渠道代理行为。测试中的无持久化渠道（ID 为 0）使用显式传入的代理配置。

已发出的请求无法撤回或改变既有连接；修改代理后以之后构建客户端的请求为生效边界。集群子节点以已应用到该节点数据库的配置快照为准；主节点配置同步完成之前，不应继续在旧节点发起敏感请求。需要跨节点绝对隔离时，应先停用相关路由/节点、完成代理配置同步，再恢复流量，并在基础设施防火墙层额外禁止无代理外连。

此策略不把某个渠道代理隐式应用到 Casdoor、邮件、汇率、独立公共价格源或集群管理通信等没有渠道上下文的系统操作。

## 浏览器登录边界

服务端渠道代理无法控制用户浏览器打开官方授权页面时的网络出口。设备码申请、轮询、换票与刷新由服务端执行，受上述策略约束；浏览器中登录/扫码/确认授权仍使用浏览器或系统的网络设置。对出口一致性敏感的账号，必须为浏览器另行配置同一代理出口，不应反向代理官方登录页面或导出浏览器 Cookie 来绕过限制。

## 验证

自动测试使用本机 HTTP 正向代理、HTTPS CONNECT、SOCKS 协议夹具与独立 SQLite 数据库验证：正常请求与重定向经代理；代理拒绝/断连/不可达时目标零直连；过期路由和异步任务快照使用当前代理；渠道不存在或策略查询失败零网络；无代理配置保持既有行为。

本机代理夹具测试不是线上账号或运营商出口验收，也不保证第三方代理自身不会泄露真实出口。严格账号保护还需要可信代理、受控浏览器与主机/容器网络访问规则配合。
